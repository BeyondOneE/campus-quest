# 局域网 HTTPS 直连

[English](lan-access.en.md)

2026-11-03 已核实当前开发电脑的 Wi-Fi 地址为 `192.168.50.136`。手机必须位于同一个可互通的局域网；直接连接电脑，不使用 Cloudflare 或其他外部转发。用户手机是否能够实际连到电脑，尚未测试。

## 当前手机入口

1. 在 iPhone Safari 打开 `http://192.168.50.136:4181/`。此安装页只提供说明和公开测试证书，不能访问业务 API 或私钥。
2. 下载名为 **Campus Quest LAN Development CA** 的证书，由用户亲自在“设置 → 通用 → VPN 与设备管理”中安装已下载的描述文件。
3. 在“设置 → 通用 → 关于本机 → 证书信任设置”中，对这个开发证书启用完全信任。见 [Apple 说明](https://support.apple.com/en-gb/102390)。
4. 打开 `https://192.168.50.136:4443/treasure-lab/`。应当没有证书警告后再开启定位或相机；不要绕过 Safari 的安全警告，应检查证书、地址与设备日期。

脚本不会自动安装或信任证书。信任该根证书意味着接受其私钥签发的证书，应保护私钥，测试后移除手机上的描述文件。根证书有效 30 天，服务证书有效 7 天；公开根证书指纹显示在安装页，并在生成时输出。脚本没有修改电脑或手机的信任库。

## 一键启动

在 `/home/beyondonee/projects/campus-quest` 运行：

```sh
./start.sh
```

也可以在其他目录使用脚本绝对路径。需要 Linux / Ubuntu、Python 3、Node.js 24 或更新版本、OpenSSL 和 `ip` 命令。运行服务只用 Node 内置模块，启动脚本不会安装依赖或构建旧 React 演示。

脚本选择实际已分配的私网 Wi-Fi IPv4（或无歧义的默认路由局域网地址），检查证书，在后台启动后端及局域网 HTTPS / 安装页代理，再验证三个入口，最后打印当前手机地址与安装页地址。重复运行会复用配置匹配、已脱离终端的健康进程。旧终端进程、IP / 来源变化、服务证书更新或显式重启时，仅替换经核实的本仓库服务。关闭启动终端后服务继续运行；它不安装开机服务或崩溃自动重启守护。

```sh
./start.sh status
./start.sh restart
./start.sh stop
# 多网卡时明确选择已分配地址：
./start.sh --ip 192.168.50.136
```

任一入口不可用时 `status` 返回状态码 1，`--json` 输出机器可读结果。日志追加到被忽略的 `.local/backend.log` 和 `.local/lan-proxy.log`；私密进程元数据 / 锁文件为 `.local/services.json` 与 `.local/services.lock`。停止保留数据库、账号、房间、领取和证书。发信号前核对进程工作目录、Node 入口和启动时间，不能仅凭 PID 文件停止进程；不动占用端口的其他程序，而是报告启动失败。命令锁避免并发启停冲突，启动失败只清理本次新启动的进程。

复用有效根证书；服务证书缺失、地址不符、临近到期或密钥不匹配时，使用原根重新生成服务证书。根证书不完整、无效、密钥不匹配或临近到期则报错，不自动替换手机信任。手机仍由用户手动安装 / 信任根证书。脚本不上传设备数据，不改信任库 / 防火墙，不删除运行数据库，也不启用外部转发。

隔离测试 / 其他本地端口可选用 `CQ_BACKEND_PORT`、`CQ_TLS_PORT`、`CQ_SETUP_PORT` 覆盖默认 4180、4443、4181。端口须互不相同且在 1024–65535。启动器自动传递后端准确 `PUBLIC_ORIGIN` 和代理目标，同源 / 回环边界不变。

## 手动启动

在仓库运行，使用实际分配给电脑的 Wi-Fi 地址：

```sh
python3 scripts/setup_lan_tls.py 192.168.50.136
PUBLIC_ORIGIN=https://192.168.50.136:4443 npm start
```

保持后端运行，在另一个终端执行：

```sh
npm run start:lan
```

后端仍在本机端口 4180，TLS 代理仅绑定 Wi-Fi 地址的 4443 端口，转发到固定后端。安装服务仅绑定同一地址的 4181 端口，只提供 `/` 与 `/campus-quest-root.cer`。没有配置路由器转发、外部服务、系统证书安装或防火墙变更。

证书和私钥在被忽略的 `.local/lan-tls/` 生成，目录私密，私钥仅属主可读写。脚本复用当前开发根证书并重新生成服务证书；CA 文件不完整会报错，不擅自替换信任。IP 变化后，使用新私网地址重新执行生成脚本，更新 `PUBLIC_ORIGIN`，并重启两个进程。地址或端口变化会改变浏览器来源，原有访客 Cookie 可能不适用。

## 验证与限制

电脑侧已用明确指定的开发 CA 验证证书链与正确 IP、拒绝错误主机名，验证两个独立 HTTPS 访客加入同一场次、Secure Cookie 及私密文件阻止。没有关闭证书验证，没有使用设备位置或相机画面；这些检查不证明手机已经信任证书、网络可达或现场通过。

普通局域网 HTTP 可显示网页，但定位与相机采集需要安全上下文，见 [MDN](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts/features_restricted_to_secure_contexts)。路由器或受管 Wi-Fi 可能隔离设备；手机打不开安装页时，先确认同网和设备互访条件。本次没有自动更改防火墙规则。此服务仍是临时开发入口，仅在电脑上的两个进程运行时可用。
