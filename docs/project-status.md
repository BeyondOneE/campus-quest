# 项目状态

[English](project-status.en.md)

更新于 2026-11-11（Asia/Shanghai）。英文寻宝通过电脑共享后端和局域网 HTTPS 运行。房间菜单提供 **Outdoor**（GPS）和 **Indoor**（RoNIN）。新房间默认 Indoor，使用四位数字。登录后可查看排行榜名次和宝藏图鉴。新版已通过自动化和桌面浏览器检查，可从局域网 HTTPS 访问。

## 已确认决策

- 正式项目名 `campus-quest`，远程仓库 `BeyondOneE/campus-quest`。
- 主要在用户 Ubuntu 电脑上开发。
- 交付形式为手机网页。第一阶段仅适配用户 iPhone Safari；Android、其他 iOS 浏览器、微信内置浏览器、小程序与原生 App 不在当前验收范围。
- 先验证相机、姿态、定位，再制定完整业务开发计划。原始源码交接包保留在课程工作区。
- 2026-11-04 用户批准方向箭头 → 近处宝箱 → 对准 / 停留 → 手动 Claim。房主手动埋藏保留作测试工具；正式方向为系统生成或工作人员布置，目前尚未实现正式布置流程。
- 当前阶段先验证手机定位触发宝藏、相机画面展示与收集的可行性，再依据实测结果确定首版范围、三项核心功能和最终验收目标。当前仅授权最小验证，不将道路对齐或地面锚定列作该实验前提。
- 用户指定由 Claude 负责前端视觉设计，Codex 负责后端、接口和功能逻辑。产品界面从现在起直接使用英文；维护文档仍保留中英两份。见 [交接与逻辑接口](frontend-handoff.md)。
- 用户要求从本阶段起采用电脑运行后端、手机浏览器连接同一服务的结构，为后续多人游玩准备。手机保留定位与相机交互，后端掌管场次、共享点、领取资格与凭据；定位开启后的数据共享在页面说明。
- 用户提出直接通过局域网访问，当前按同网手机直连准备，不启用 Cloudflare。HTTPS 采用独立开发证书；手机安装和信任须由用户亲自完成，没有自动修改信任库或绕过证书警告。

## 后续工作

当前以用户提出并授权的“定位寻宝、相机展示”进行最小验证。道路标记、实测道路坐标和连续空间对齐属于此前讨论的候选，不作为本次实验的前置工作；没有因此承诺最终产品目标。

- 电脑运行 `./start.sh` 后台拉起后端和局域网 HTTPS，用 `./start.sh status`、`restart`、`stop` 管理。手动只开后端仍可 `npm start`，在 `http://127.0.0.1:4180/treasure-lab/` 提供英文页面与 [业务 API](backend-api.md)。创建者设置共享测试点，其他手机可用同一场次码加入；确认离开后可开启 AR 方向，稳定返回、对准并停留后手动 Claim；按 [现场步骤](treasure-lab.md) 验证离开 / 返回、相机与收集。
- 定位初始参数为领取半径 3 米、报告精度门槛 20 米、边界缓冲 10 米、有效位置最长 15 秒、进入观察至少 2 秒。当前 AR 瞄准用 18° 容差和 700 ms 停留，姿态最长 1500 ms，帧龄最长 750 ms。新的瞄准参数待手机测试。
