[English](project-status.en.md)

更新日期：2026-11-04（Asia/Shanghai）。英文寻宝已接入电脑共享后端，并准备局域网 HTTPS 直连；页面已改为不滚动的分屏界面并重做视觉与动效，密码不再限制最短长度。自动化、HTTP 与电脑侧 TLS 已检查；硬件实测仍来自 2026-10-28，手机证书信任和实际可达尚待用户操作，未新增 Safari 现场验收。

## 已确认决策

- 正式项目名 `campus-quest`，远程仓库 `BeyondOneE/campus-quest`。
- 主要在用户 Ubuntu 电脑上开发。
- 交付形式为手机网页。第一阶段仅适配用户 iPhone Safari；Android、其他 iOS 浏览器、微信内置浏览器、小程序与原生 App 不在当前验收范围。
- 先验证相机、姿态、定位，再制定完整业务开发计划。原始源码交接包保留在课程工作区。
- 当前阶段先验证手机定位触发宝藏、相机画面展示与收集的可行性，再依据实测结果确定首版范围、三项核心功能和最终验收目标。当前仅授权最小验证，不将道路对齐或地面锚定列作该实验前提。
- 用户指定由 Claude 负责前端视觉设计，Codex 负责后端、接口和功能逻辑。产品界面从现在起直接使用英文；维护文档仍保留中英两份。见 [交接与逻辑接口](frontend-handoff.md)。
- 用户要求从本阶段起采用电脑运行后端、手机浏览器连接同一服务的结构，为后续多人游玩准备。手机保留定位与相机交互，后端掌管场次、共享点、领取资格与凭据；定位开启后的数据共享在页面说明。
- 用户提出直接通过局域网访问，当前按同网手机直连准备，不启用 Cloudflare。HTTPS 采用独立开发证书；手机安装和信任须由用户亲自完成，没有自动修改信任库或绕过证书警告。

- 从 2026-10-28 交接包导入六页 React 原型，保留原始来源清单与 proposal。
- 原包 ZIP 与已解压文件逐一一致，包内 SHA256 校验通过。
- 原 `dist` 已在桌面浏览器走通六页流程，包括错误答案、正确结算及刷新恢复。
- 增加独立 Safari 硬件验证页及本地静态服务器。
- 增加 `/treasure-lab/` 英文功能页、远程 API 适配器和 Node / SQLite 后端。访客可创建或加入场次，共享单个宝藏点；后端检查离开与返回，并持久化每人一次的领取凭据。当前规则是实验初值，未确定最终多人玩法。
- 增加开发证书生成脚本、仅绑定 Wi-Fi 地址的 HTTPS 代理和证书安装页；后端仍在本机端口，未配置路由器或防火墙。见 [局域网接入](lan-access.md)。
- 增加本地账号注册 / 登录 / 退出、跨设备恢复成员与凭据、注册关联访客进度及各登录会话独立定位判定。运行数据库升级前已私密备份，原房间 / 玩家 / 领取记录条数保持一致。见 [账号 API](backend-api.md) 与 CQ-20261103-010。
- 修复原锁文件中七个只有 `optional: true`、没有版本信息的 Rollup 条目；由 npm 补全可选依赖元数据。

## 后续工作

当前以用户提出并授权的“定位寻宝、相机展示”进行最小验证。道路标记、实测道路坐标和连续空间对齐属于此前讨论的候选，不作为本次实验的前置工作；没有因此承诺最终产品目标。

- 电脑运行 `npm start`，在 `http://127.0.0.1:4180/treasure-lab/` 提供英文页面与 [业务 API](backend-api.md)。创建者设置共享测试点，其他手机可用同一场次码加入；按 [现场步骤](treasure-lab.md) 验证离开 / 返回、相机与收集。
- 默认领取半径 30 米，定位报告精度门槛 20 米，边界缓冲 10 米，有效位置最长 15 秒，进入观察至少 2 秒。这些是待走测的实验初值，不是已通过的验收指标。
- 本轮只验证单个共享点；人工划分完整校园区域、地图、定时刷新、学生身份验证与完整成绩系统尚未实现。已有本地密码账号及临时访客模式，密码找回和学校统一登录尚未实现。实验暂按每人每轮各领取一次，不采用竞争抢夺。
- 共享点坐标与领取结果保存到被忽略的 SQLite；玩家最近位置仅在后端内存判定，不保存轨迹；相机画面不上传。客户端位置和相机状态并非可信硬件证明，不宣称防作弊。

- 手机在同一可互访网络中手动安装并信任开发证书后再测；不能由电脑侧证书验证推定手机可用。此前被拒绝的 Cloudflare 保持关闭，不再以外部转发作为本轮测试前提。
