# 定位寻宝最小验证

[English](treasure-lab.en.md)

用户于 2026-11-03 同意先验证“真实定位触发宝藏 → 相机画面展示 → 点击收集”，随后要求从现在起采用电脑后端与手机网页连接的结构。入口为 `/treasure-lab/`，独立于六页业务演示与硬件诊断页。已支持访客场次、多设备共享单个测试点及持久化领取；校园地图、区域编辑、定时刷新、学生身份验证和最终多人玩法尚未实现。本地用户名 / 密码注册、登录和退出已可用，见 [账号接口](backend-api.md)。

## 启动与访问

在开发仓库运行：

```sh
npm start
```

电脑预览：`http://127.0.0.1:4180/treasure-lab/`，使用已验证的 Node.js 24.19.0。手机现使用 [局域网 HTTPS 安装步骤](lan-access.md)，后端设置准确 `PUBLIC_ORIGIN`，并由用户亲自在手机安装和信任开发证书。手机不能用电脑的 localhost 地址。Cloudflare 保持关闭，没有外部转发或长期部署；手机信任与可达仍待确认。

Node 服务提供两个页面共九个白名单静态文件与 [后端 API](backend-api.md)，不开放仓库、目录列表或任意文件上传。Python 服务现在仅提供原硬件诊断；单独运行 Vite 或静态构建不能替代业务后端。

## 现场步骤

1. 在手机 Safari 打开同一个 HTTPS 测试网址，输入昵称，点击“Create session”。其他手机使用场次码和自己的昵称点击“Join session”。也可以先注册或登录账号；已登录玩家使用账号用户名，重进原房间恢复原身份与领取记录。注册保留当前访客场次，登录不合并其他访客进度。输入凭据前应确认可信 HTTPS。
2. 在方便往返的室外地点，阅读位置共享说明，点击“Start live location”并确认权限。位置会发给电脑后端作判定，页面不会自动申请定位或相机权限。
3. 创建者等到位置有效，设置领取半径，点击“Place shared treasure here”。其他玩家共用该测试点；只有创建者能重新放置，重新放置会开始新轮次。
4. 各玩家保持页面前台，走出范围，直到提示已记录离开；再返回中心附近，等待宝藏解锁。精度不足、边界不确定、样本过期或后端断联时暂停领取。
5. 点击“Open camera”并允许权限。真实画面更新后才显示可点击宝箱；点击后由后端重新检查资格并记录凭据，再释放相机。实验规则为每位玩家每轮各领取一次。
6. 展开“Field notes”，填写实际观察并导出报告。刷新后通过 Cookie 恢复当前身份和后端领取结果；相机与定位仍需手动开启。后端重启会清空临时位置观察，但保留共享点与领取凭据。

## 实验参数与判定

| 参数 | 初始值与规则 |
| --- | --- |
| 领取半径 | 默认 30 米，可设置 15–100 米 |
| 定位质量 | 系统报告精度不超过 20 米；设置地点和领取均要求有效位置 |
| 位置时效 | 最长 15 秒；明显的未来时间戳不接收 |
| 确认离开 | 距离减去报告精度，至少为领取半径加 10 米 |
| 确认进入 | 距离加上报告精度不超过领取半径；至少两次不同时间戳的有效更新，跨度至少 2 秒 |
| 允许收集 | 已确认离开并返回；当前仍满足进入条件；相机处于播放状态且最近 2.5 秒内观察到画面更新 |

这些值是实现可行性实验的初始参数，不是用户已确认的最终验收标准。判定利用系统报告的不确定性作保守筛选，但报告精度不是实际误差保证；宝藏中心也来自一次有误差的系统定位，没有经过测绘校准。选择较小半径可能需要更好的定位。不能用本页证明楼层定位、物理点位精确匹配或抵抗位置伪造。

## 生命周期与隐私

- 切后台或离开页面会停止定位、释放相机并取消尚未完成的相机申请；返回后手动开启。页面尝试通知后端停止；通知未送达时，已有位置也会按时效过期。
- 失去有效位置会暂停领取并关闭正在运行的相机。重新满足条件后手动开启相机。权限拒绝可在 Safari 网站或系统设置中调整后重试。
- 相机画面仅作为实时背景；宝箱是 CSS 绘制的游戏对象，没有地面锚定、道路对齐或姿态跟踪。
- 点击开启后，坐标发送给电脑后端；共享宝藏点写入私密 SQLite，玩家的最近位置只留后端内存，不保存轨迹。后端停止定位或重启会清空最近位置。相机画面不上传，报告仍不自动包含坐标。使用外部 HTTPS 转发时，提供方可以处理转发流量，需先明确获准。
- 报告包含实验参数、放置时的报告精度、距离、状态变化、收集次数、相机帧观察和手写备注。备注由用户填写，分享前自行检查；原始报告由 `.gitignore` 忽略，不进入 Git。

## 验证边界

自动化测试使用隔离样本检查逻辑、浏览器边界与两个客户端的后端状态，不向实际页面或运行中的数据库注入虚假坐标。桌面检查确认英文界面、真实 HTTP 会话、刷新恢复与服务边界；不替用户授予硬件权限。当前仍需 HTTPS 手机入口和上述 Safari 现场流程，核实触发时机、位置波动、相机体验及后台恢复。自动化、构建通过不代表多人真机或校园走测通过。
