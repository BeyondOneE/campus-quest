# 定位寻宝最小验证

[English](treasure-lab.en.md)

右上角房间菜单提供 **Outdoor** 和 **Indoor**。切换会开启新的房间轮次。[RoNIN 与模式切换](indoor-demo.md)

当前玩法：[2026-11-05 近场搜索](near-field-search.md) 取代下文最后 GPS 3 米领取 / 绝对罗盘门槛。GPS 解锁 15 米遭遇，再在短时本地坐标系转动搜索瞄准；滑条用于离开距离。

用户于 2026-11-03 同意先验证“真实定位触发宝藏 → 相机画面展示 → 点击收集”，随后要求从现在起采用电脑后端与手机网页连接的结构。入口为 `/treasure-lab/`，独立于六页业务演示与硬件诊断页。已支持访客场次、多设备共享单个测试点及持久化领取；校园地图、区域编辑、定时刷新、学生身份验证和最终多人玩法尚未实现。本地用户名 / 密码注册、登录和退出已可用，见 [账号接口](backend-api.md)。

## 启动与访问

在开发仓库运行：

```sh
./start.sh
```

电脑预览：`http://127.0.0.1:4180/treasure-lab/`，使用已验证的 Node.js 24.19.0。手机现使用 [局域网 HTTPS 安装步骤](lan-access.md)，后端设置准确 `PUBLIC_ORIGIN`，并由用户亲自在手机安装和信任开发证书。手机不能用电脑的 localhost 地址。Cloudflare 保持关闭，没有外部转发或长期部署；手机信任与可达仍待确认。

Node 服务提供两个页面共十一个白名单静态文件与 [后端 API](backend-api.md)，不开放仓库、目录列表或任意文件上传。Python 服务现在仅提供原硬件诊断；单独运行 Vite 或静态构建不能替代业务后端。

## 现场步骤

1. 在手机 Safari 打开同一个 HTTPS 测试网址，点击“Create a room”并输入昵称。其他手机点“Join with a code”，输入或粘贴四位数字房间号，再填写自己的昵称。已有八位码仍可使用。房间码可以包含小写、空格和连字符，格式有误时会在输入框旁提示。已登录玩家使用账号用户名。登录后从选房页开始，凭房间号重进开放房间可恢复账号身份与领取记录。注册保留当前访客场次。输入凭据前应确认可信 HTTPS。
2. 在方便往返的室外地点，阅读位置共享说明，点击“Turn on location”并确认权限。位置会发给电脑后端作判定，页面不会自动申请定位或相机权限。
3. 创建者等到位置有效，点击“Hide treasure here”。房主可在放置前到 **Menu → Test tools** 调整 **Departure distance**。其他玩家共用该测试点，只有创建者能从菜单或领取后的页面移动宝藏，移动会开始新轮次。
4. 保持页面前台，走出范围，直到确认已离开。点击“Open AR directions”，允许后置相机与 Motion & Orientation；竖持手机，后置相机朝地平线，跟着箭头返回。箭头直接指向目标，不提供道路路线。
5. 稳定返回范围内后，宝箱的虚拟方向进入视野时才出现。将相机对向宝箱并保持约 0.7 秒，再点“Claim treasure”。转开手机、指南针过期、视频停帧均禁用 Claim；精度不足、边界不确定或断联也暂停领取。后端重新校验定位与瞄准，记录每人每轮一次领取，再释放相机。
6. 用 **Menu → Test tools → Field notes and report** 填写实际观察并导出报告。刷新后通过 Cookie 恢复身份和领取结果，相机和定位需手动开启。后端重启会清空临时定位状态，保留共享点和领取凭据。
7. 点 **Menu → Leave room** 并确认，返回选房页。房主离开或登出时，房间对所有人关闭。要重新演示，房主也可以用 **Menu → Test tools → Reset demo** 关闭当前房间。

## 实验参数与判定

| 参数 | 初始值与规则 |
| --- | --- |
| 领取半径 | 默认 3 米，可设置 3–100 米 |
| 定位质量 | 系统报告精度不超过 20 米；设置地点和领取均要求有效位置 |
| 位置时效 | 最长 15 秒；明显的未来时间戳不接收 |
| 确认离开 | 3 米模式按报告中心距离大于 3 米；更大半径仍用距离减精度至少达到半径加 10 米 |
| 确认进入 | 3 米模式按报告中心距离不超过 3 米；更大半径计入误差圈。至少两次不同时间戳有效更新、跨度至少 2 秒 |
| 方向相机 | 已确认离开且位置新鲜有效，包含 outside / boundary |
| 允许收集 | 近场遭遇有效，帧龄不超过 750 ms，姿态不超过 1500 ms，角误差在 18° 内至少停留 700 ms |
| 瞄准停留 | 至少三个不同时间戳样本、间隔不超过 900 ms；后端按收到时间计算，手机同时独立检查 |

这些值是实现可行性实验的初始参数，不是用户已确认的最终验收标准。判定利用系统报告的不确定性作保守筛选，但报告精度不是实际误差保证；宝藏中心也来自一次有误差的系统定位，没有经过测绘校准。选择较小半径可能需要更好的定位。不能用本页证明楼层定位、物理点位精确匹配或抵抗位置伪造。

## 生命周期与隐私

- 切后台或离开页面会停止定位、释放相机并取消尚未完成的相机申请；返回后手动开启。页面尝试通知后端停止；通知未送达时，已有位置也会按时效过期。
- 失去有效位置会暂停领取但保留已开启相机，显示 GPS 转圈并自动恢复 watch；新位置和瞄准通过后继续。权限拒绝可在 Safari 网站或系统设置中调整后重试。
- 相机画面仅作为实时背景；宝箱跟随绝对后置相机姿态与屏幕旋转，接近时锁定方位以减轻 GPS 抖动；该虚拟目标不具备地面锚定、视觉 SLAM、测绘物理点匹配或道路对齐。
- 点击开启后，坐标发送给电脑后端，瞄准时也上报临时姿态 / 帧龄；共享宝藏点写入私密 SQLite，玩家的最近位置只留后端内存，不保存轨迹。后端停止定位或重启会清空最近位置。相机画面不上传，报告仍不自动包含坐标。使用外部 HTTPS 转发时，提供方可以处理转发流量，需先明确获准。
- 报告包含实验参数、放置时的报告精度、距离、状态变化、收集次数、相机帧观察和手写备注。备注由用户填写，分享前自行检查；原始报告由 `.gitignore` 忽略，不进入 Git。

## 验证边界

自动化测试使用隔离样本检查逻辑、浏览器边界与两个客户端的后端状态，不向实际页面或运行中的数据库注入虚假坐标。桌面检查确认英文界面、真实 HTTP 会话、刷新恢复与服务边界；不替用户授予硬件权限。当前仍需 HTTPS 手机入口和上述 Safari 现场流程，核实触发时机、位置波动、相机体验及后台恢复。自动化、构建通过不代表多人真机或校园走测通过。

## 当前测试范围与下一次走测

房主手动埋藏保留作方便测试的入口；用户设想的正式产品由系统生成或工作人员布置，两个正式布置流程都尚未实现。见 CQ-20261104-008 与 [瞄准接口](backend-api.md#ar-方向与瞄准契约2026-11-04)。

在室外 Safari 用已知地标核对多个朝向的箭头，转开再转回、倾斜 / 旋转手机、穿越边界、保持 / 中断瞄准、拒绝后重试姿态权限，最后切后台再手动恢复。用 Field notes 记录磁场干扰、GPS 摆动、目标抖动和实际 Claim 表现。Motion & Orientation 被拒后，检查权限并用“Enable direction”重试；指南针缺失、姿态过期或精度不足时禁止 Claim，不退回仅凭定位领取。当前没有这些实测结果。

相机向导：点击 **Chat with guide** 输入文字或快捷提问。面板关闭时可主动介绍已配置建筑 / 课程，并约每 30 秒提示距离；当前未填校园资料与 Key，预设回复明确标注。见 [接入与内容字段](ai-guide.md)。3 米模式按近似报告距离、可能受 GPS 漂移影响，旧 10 米缓冲不适用于 3 米。已有存储点已在私密备份后迁移，没有移除领取记录。
