## CQ-20261104-001 · Non-scrolling screens, password rule and flow statement correction

### Goal and result

After reviewing Codex's handoff, the user raised three points: the CQ-20261103-009 flow is only provisional for testing, not the final design; a 15-character password does not suit a small student game and passwords should be free-form; the page interaction is cluttered and the game should not be a scrolling page.

- Corrected the "user accepted the interaction logic" wording in project status, the handoff and the brief. The original CQ-20261103-009 record is retained; this entry takes precedence.
- Passwords are now 1–128 characters; empty and over-long passwords are still rejected. Username rules, login throttling and scrypt hashing are unchanged. The user decided against a strength rule; accounts with weak passwords are easier to guess, which is an accepted trade-off.
- `/treasure-lab/` is rebuilt as three full-screen views (entry, field, camera) that follow session state, and the page itself does not scroll. Each state offers one main action; the player list, account, moving the treasure, switching rooms, field notes and hardware diagnostics moved to bottom sheets.

### Decisions, changes and links

- Changed `public/treasure-lab/index.html`, `style.css` and `app.js`. No static files were added, so the backend allowlist and CSP needed no change. Location, camera, background cleanup and late-stream cancellation logic are retained; claim gates and location parameters are unchanged.
- The distance ring only shows leave / return progress, not direction: the backend does not send treasure coordinates, so the page should not imply direction data exists.
- Changed password validation in `server/store.mjs` and reworded the missing-room message to "Room not found". Claude made this change directly with the user's authorization; Codex was not involved in this change.
- Regenerated `docs/frontend-dom-contract.json` (88 elements with IDs) and updated the API, field-step and handoff docs. Some control IDs changed, for example `create-room` / `join-room` became `show-create`, `show-join` and `entry-submit`.
- The flow itself was not redesigned: place → leave → return → claim is set by backend rules and only its presentation changed. The final gameplay awaits the user's decision.

## CQ-20261104-002 · Visual and motion redesign

### Goal and outcome

- Problem to solve: the user is satisfied with the interaction but said the course project is graded by non-specialists and wants a higher visual standard; the design lacked impact, had no animation, and interactions switched abruptly. This feedback did not state its viewing environment and is not iPhone Safari acceptance.
- Actually completed: redid the `/treasure-lab/` visuals and added motion throughout; interaction structure, wording logic and backend rules are unchanged. Incomplete: appearance and performance on a real phone are unchecked.

### Decisions, changes and references

- Core concept: one round is one night. The sky follows progress from dusk (hide) through deep night (leave), pre-dawn (return) and dawn (ready) to sunrise (claimed), with the moon setting, the sun rising and campus-silhouette lights fading. The silhouette is a generic illustration and does not depict real campus buildings.
- Transitions: leaving elements animate as decorative copies while real state and `hidden` still change synchronously, so tests and accessibility semantics are unchanged. The camera opens like an iris, sheets slide, layout changes glide and the distance number rolls.
- Reward moments: particles fire only when the round moves forward, not on resume or a room change. Claiming brings a full-screen flash, the chest lid opening and a burst of coins and sparks. Gauge pings quicken with progress but carry no direction: the backend does not send treasure coordinates to the page.
- `prefers-reduced-motion` is respected and missing browser capabilities are skipped. No static files or external resources were added, so the backend allowlist and CSP are unchanged and no backend restart is needed.
- Changed `public/treasure-lab/index.html`, `style.css` and `app.js`, and regenerated `docs/frontend-dom-contract.json`. No implementation hash exists before commit.

## CQ-20261104-003 · Menu jolt fix and visual simplification

### Goal and outcome

- Problem to solve: the user reported the whole page jolting when the menu opens, is satisfied with the motion and fonts, but finds the picture too flashy and slightly cluttered. This feedback did not state its viewing device and is not iPhone Safari acceptance.
- Actually completed: fixed the jolt's root cause and reduced decoration. Transitions, the claim ceremony and fonts are kept. Incomplete: the result on the user's iPhone is unconfirmed.

### Decisions, changes and references

- Jolt cause: the sheet took focus while still animating below the screen, so the browser scrolled the `.app` container to reveal it. Now uses `focus({ preventScroll: true })`, the container uses `overflow: clip` (falling back to `hidden` on older browsers), and the sheet slides in without overshoot, which could expose its bottom edge.
- Simplification principle: one visual focus at rest, with continuously looping decoration giving way to motion that follows an action. The sky-follows-progress concept stays, at lower saturation.
- Removed: entry rays and twinkles, gauge ticks, the looping button shine, looping status and progress-node pulses, camera rays, flickering campus windows and trees.
- Reduced: dust appears only on entry and in smaller numbers, fewer stars, smaller moon and sun halos and gold glows, a smaller chest, and location readouts changed from two cards to one line of small text.
- Changed `public/treasure-lab/index.html`, `style.css` and `app.js`, and added a regression test to `tests/treasure-lab.test.mjs`. Element IDs are unchanged, so the DOM contract needs no update. No implementation hash exists before commit.
