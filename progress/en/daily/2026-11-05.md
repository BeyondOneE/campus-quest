## CQ-20261105-001 · Near-field claim feasibility with motion sensors

### Goal and outcome

The user reports inadequate GPS precision for the final treasure search and proposes switching to the phone gyroscope / accelerometer nearby. Source inspection confirms the live design still requires reported GPS distance within 3 m, valid absolute compass orientation and a 1200 ms aim hold. The proposal has not changed those rules or product code.

### Decisions, changes and references

Gyroscopes support short-term relative rotation; accelerometers provide motion / gravity-related information. Pure inertial displacement accumulates error and cannot remove the starting GPS error. Proposed experiment: GPS grants coarse nearby eligibility, then a short local encounter fixes a virtual target direction and uses relative orientation for searching / centring. Avoid interpreting integrated phone acceleration as precise walking distance. Coarse confirmed departure, expiry and background return need explicit reset rules. A candidate 10–15 m encounter radius is a discussion value only; it does not replace the user’s existing 3 m setting without a new decision. Precise shared physical placement would additionally need an external reference such as a reviewed visual marker; visual-inertial tracking alone does not resolve an incorrect geographic anchor.

References checked: [W3C Device Orientation and Motion](https://www.w3.org/TR/orientation-event/), [Cambridge inertial-navigation principles and error analysis](https://www.cl.cam.ac.uk/techreports/UCAM-CL-TR-696.pdf), [Apple visual-inertial world tracking](https://developer.apple.com/documentation/ARKit/managing-session-life-cycle-and-tracking-quality). The older Cambridge report is used for error mechanisms, not quantitative accuracy predictions for the user’s current phone. Apple’s native framework is a conceptual reference, not proof that this Safari page provides it.
